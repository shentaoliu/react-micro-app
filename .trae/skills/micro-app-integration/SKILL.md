# React 微前端子应用接入

将指定子应用接入现有主应用，并保留独立运行能力。支持调查、计划、实现、审查；只执行用户授权的阶段。不要把某次接入代码当作通用模板。

## 确定任务输入

从用户请求、工作区与源码确认：主子应用目录、应用名、服务地址、挂载入口、独立路由、通信要求及验收范围。不要硬编码本机路径、端口或子应用名称。

信息可从代码查到时先查；只有影响方案且无法确认的信息才询问用户。不能访问子项目时报告缺口，不猜测。

## 调查与方案

1. 阅读项目规则、Git 状态和相关 diff，区分本次任务与已有修改。
2. 检查两端入口、路由、开发服务器、资源路径、跨域、类型声明、挂载与卸载方式。确认实际框架及 micro-app 版本，依据安装包类型、源码或对应版本官方文档选择 API。
3. 明确路由模式与其 URL 行为，再确定主应用路由匹配和子应用 basename；不要直接假定所有模式都使用 pathname 子路径。检查直接访问、内部导航、刷新、前进后退和主菜单选中态。
4. 给出必要文件及职责、实现方案、风险和验收方法。小任务简要说明即可，不强制所有任务经过人工逐步批准；用户明确要求先规划时只提供计划。

## 实施

- 先完成最小挂载、内部导航、独立运行，再补充加载、错误、重试等本次要求的能力。
- 生命周期事件的绑定时机须覆盖快速或缓存加载；确认事件派发目标和冒泡行为，不假设自定义元素事件等同于 React 合成事件。
- 重试必须实际重新触发加载，核实当前版本的实例缓存与销毁行为。只清空错误文字不算重试；不刷新整个主应用。
- 检查 React root 销毁、当前实例监听清理及重复进入的行为。兼容实际启用的 StrictMode、保活或缓存机制；不无条件删除其他订阅。
- 通信优先复用现有协议。验证输入、晚挂载读取最新配置和监听清理；不同 origin 的 localStorage 不是跨应用实时通信。
- 不为接入默认关闭沙箱、升级依赖或重构无关模块。

## 验证与交付

读取 [验收清单](references/acceptance.md)，按实际变更选择相关场景。运行现有适用脚本；两端的构建与类型检查能力需分别确认。

审查任务相关 diff。遇到失败先定位，区分原有问题、本次问题和环境限制，避免扩大范围。

输出修改文件、关键选择、执行的检查及结果、用户报告的验收和剩余未验证项。没有浏览器工具或运行条件时提供复现步骤，明确待人工验证；不声称已通过。

## 本项目导航线索

仅在当前仓库使用这些入口，并在执行时重新确认：主应用 `src/main.tsx`、`src/router/index.tsx`、`src/theme.tsx`；子应用通常有独立入口、路由与主题模块。现有 `SubAppA` 可供调查，不是已经证明正确的通用方案。详细教学文档是项目根目录下 `docs/micro-app-integration.md`，按需读取，其中历史起点不代表当前状态。
