# 微前端接入验收

按任务选择场景，记录实际 URL、操作、预期、结果和证据来源。未执行的场景写“未验证”，不要预先打勾。

| 场景 | 检查内容 |
| --- | --- |
| 独立运行 | 子应用首页和内部路由可访问、刷新 |
| 嵌入运行 | 主应用入口可挂载，布局与菜单正常 |
| 路由 | 内部跳转、刷新、前进后退符合选定模式，容器不意外消失 |
| 离开再进入 | 重复数次，无重复 root、监听或空白 |
| 加载中 | 提示出现，完成后退出 |
| 加载失败 | 有提示和可操作的恢复入口，不永久停留在加载态 |
| 重试 | 恢复服务后实际重新加载，只影响目标子应用 |
| 主题通信 | 已挂载时更新；先换主题再挂载也获得最新值 |
| 回归 | 主应用原有路由、其他子应用、独立运行不受影响 |

## 可靠地复现加载失败

停止服务不会让已加载页面自动报错。触发新的资源加载，禁用浏览器缓存或使用请求阻断；记录所用方法。随后恢复服务或解除阻断，再点重试。

## 故障反馈信息

收集运行模式、实际 URL、复现步骤、预期与实际结果、相关报错或失败请求。判断问题属于资源请求、挂载、路由、通信还是卸载，再做最小修复并验证受影响场景。

## 检查的证据边界

构建证明可以打包，不证明路由和生命周期正确；lint 不代替类型检查；静态阅读不证明没有重复订阅。分别标记工具实测、用户验收和静态推断。
