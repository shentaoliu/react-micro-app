# TRAE 项目规则与 Skill 使用

## 已创建的配置

- `.trae/rules/project.md`：始终生效的主应用项目约定，覆盖修改范围、技术栈、主题机制和验证要求。
- `.trae/skills/micro-app-integration/SKILL.md`：接入或排查 micro-app 子应用时按需使用的流程。
- Skill 的 `references/acceptance.md`：按需读取的验收清单。

配置只放在主应用，没有改变全局设置，也没有复制到子应用。单独打开子应用时不要假设主应用规则自动生效；跨项目任务需让智能体读取两端代码和各自约定。

## 确认 TRAE 识别

打开主应用，确认目录可信。在设置中查找“规则”和“技能”相关页面（不同版本名称可能不同），确认项目规则存在且为始终生效、项目技能列表包含 `micro-app-integration` 且启用。

如果没有出现，先确认打开的是主应用根目录，重新打开项目或重载窗口，再查看列表。仍不能发现时，按照当前版本提供的导入入口导入 SKILL.md；避免重复创建同名技能。

文件已创建并通过结构检查，不代表已在你安装的 TRAE 3.6.13 中实测自动加载。

## 第一次只读试用

选择 Chat，发送：

```text
请使用 micro-app-integration 技能，分析当前子应用 A 的接入状态。
本轮只读取代码，不修改任何文件。
请说明你加载的技能路径，检查当前实现，输出缺口与待验证场景。
不要因为存在接入代码就认定已经验收通过。
```

检查回答依据是否来自源码和 Skill，而不只看它是否声称“已加载”。必要时在上下文中手动引用 SKILL.md；手动引用能使用其指令，但不证明自动发现已正常工作。

确认方案后选择 Agent：

```text
使用 micro-app-integration 技能，修复刚才确认的接入问题。
保留已有修改，完成必要实现和验证，列出未验证项。
```

接入新子应用时明确应用目录和目标入口；Skill 会调查实际地址、依赖和路由，不照搬子应用 A。

## 与练习文档的关系

`micro-app-integration.md` 是逐步练习教程：其中 Ask、Plan 在你当前界面都用 Chat，Agent 仍用 Agent。规则是长期约束，Skill 是某类任务的方法，教程是给人的操作说明。

## 维护

本 Skill 是基于代码调查和接入要求编写的初版，尚未收到完整运行验收记录。后续只将反复有用、验证过的方法沉淀进去；项目特定配置留在源码或任务文档中，不把单次故障升级为通用规则。

格式依据（2026-11-17 查阅）：[TRAE 规则](https://docs.trae.cn/ide_rules)、[TRAE 技能](https://docs.trae.cn/ide_skills)。采用 TRAE 的项目目录、规则 alwaysApply 和 Skill name/description 元数据；未添加 Codex 专属配置。
